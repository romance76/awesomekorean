# 포인트 · Entry · 광고 결제 구조 리포트 (확인용)

작성: 2026-10-11 UTC (애틀랜타 10-11 새벽) · 코드 조사 기준, **아직 아무것도 바꾸지 않았음**
목적: Kay 님이 정한 원칙대로 "돈 / 포인트 / Entry" 세 가지를 확실히 나누고, 포인트 → 기프트카드 교환(수수료 차감) 구조를 만들기 전에 전체 그림을 먼저 확인받기.

## 1. 한 줄 요약

|---|---|---|---|---|
| **돈 (USD 카드 결제)** | 진짜 돈 | 회원이 카드로 결제 | **모든 광고**(배너·텍스트 광고·NEW 전면광고 등) | — |

## 3. 새 구조 (제안)

### 3-1. 포인트 (커뮤니티 점수)
- **얻기**: 가입·프로필 완성·글·댓글·좋아요 받음·Q&A 채택 (지금 하루 한도 그대로). 출석 포인트는 끔.
- **쓰기**: 끌어올리기 · 채팅방 개설/입장/연장 · 장터 홀드 · 추가 사진.
- **팔지 않음**: 포인트 패키지 판매 중단(화면·서버 모두). → "포인트는 모으는 것"이 확실해지고 기프트카드 환전 통로가 막힘.
- **기프트카드로 교환 가능**(아래 4번).

### 3-2. Entry (성과 보상)
- **얻기**: 출석(5회 = 1개) · 내돈내산 리뷰 승인 · 이벤트 완료 인증 승인 · 거래/채용/공동구매 완료 · 업소 소유권 승인 · 가입/이메일 인증 보너스 · 관리자 지급.
- **쓰기**: 어코 주최 경품 추첨 응모만.
- **팔지 않음 / 교환 없음 / 만료 없음**(지금 설정: 만료 꺼짐).

### 3-3. 돈 (광고)
- 배너 광고·텍스트 광고·NEW 전면광고·이벤트 홍보·(결정 시) 상위노출 → **카드 결제만**.
- 결제 시 인보이스 자동 발행(이미 만든 인보이스 1단계 그대로 사용).

## 4. 포인트 → 기프트카드 교환 설계 (제안)

### 4-1. 기준값 (관리자 화면에서 바꿀 수 있게)
| 항목 | 제안 값 | 이유 |
|---|---|---|
| 환율 | **1,000P = $1** | 열심히 활동하는 회원 하루 최대 약 110P(글 50 + 댓글 60) → 한 달 약 3,300P ≈ $3. 비용 통제 가능 |
| 최소 교환 | **$10 카드 (10,000P)** | 처리 비용 대비 의미 있는 단위 |
| 카드 단위 | $10 / $25 / $50 | |
| **수수료** | **10% (최소 $1)** → $10 카드 = **11,000P** 차감 | Kay 요청 "수수료를 빼는 방식". 결제 대행·처리 비용 충당 |
| 월 한도 | 1인 월 1회, 월 최대 $50 | 어뷰징 방지 |
| 연 한도 | 1인 연 **$599** 이하 | 미국은 연 $600 이상 지급 시 1099 세금 서류 문제가 생길 수 있음 — **세무사 확인 필요** |

### 4-2. 신청 자격 (어뷰징 방지)
가입 30일 이상 · 이메일 인증 + 전화번호 등록 · 최근 30일 정지·신고 처리 없음 · 기프트카드 받을 이메일 확인 · 한 사람 여러 계정 금지(IP·기기 중복 확인).

### 4-3. 흐름
1. 회원: 마이페이지 › 포인트 › "기프트카드 교환" → 금액 선택 → 수수료 포함 차감 포인트 확인 → 신청
2. 서버: 신청 즉시 해당 포인트를 **보류**(잔액에서 빠짐, 장부에 '교환 대기')
3. 관리자(최고관리자): 휴대폰/PC "교환 신청" 화면에서 승인·거절(사유) — 감사 로그 기록
4. 승인 → 기프트카드 발송(처음엔 **관리자가 직접 구매해 코드 입력** 방식, 나중에 Tango Card·Giftbit 같은 발급 서비스 API 연결 가능)
5. 거절·취소 → 보류 포인트 전액 돌려줌
6. 회원에게 알림 + 메일(코드 포함), 장부에 완료 기록

### 4-4. 새로 필요한 것
- 표 `point_redemptions`(신청자·카드 금액·차감 포인트·수수료·상태·처리자·사유·발송 코드(암호화)·시각)
- 설정 `point_settings`: redeem_rate, redeem_min, redeem_fee_pct, redeem_fee_min, redeem_monthly_max, redeem_yearly_max, redeem_enabled(킬 스위치)
- 회원 화면(신청·내역), 관리자 화면(대기 목록·승인/거절·발송 입력), 비상 스위치에 "교환 멈추기"
- **약관·포인트 정책 페이지 개정**(포인트는 현금이 아님, 교환 조건·수수료·회수 조건 명시)

## 5. 바꾸는 순서 (제안, 단계마다 배포·보고)
1. **정리 1단계(안전, 바로 가능)**: 포인트 패키지 판매 중단 · 게임머니/포커 환전 끄기 · "활동 N회 Entry" 끄기 · 출석 포인트 끄기(출석은 Entry 만) · 마일스톤은 Entry 만 · 이벤트 완료 인증 → Entry · 버그 2건 수정 · 포인트 정책 안내 페이지 문구 정리.
2. **광고 돈 결제 2단계(결제 경로 필요)**: 배너 입찰·텍스트 광고(·상위노출)를 카드 결제로. **Stripe 를 계속 쓸지, CardPointe 전환을 기다릴지 결정 필요.** 기다리는 동안 대안: 광고는 "관리자에게 신청 → 관리자가 직접 등록 + 인보이스 발행(수동 결제)".
3. **리뷰 Entry 3단계**: 내돈내산 리뷰 승인 시 Entry 지급(쇼핑 기능은 미도입 확정이라, 어떤 리뷰를 말하는지 확인 필요 — 업소 리뷰? 공동구매 후기?).
4. **기프트카드 교환 4단계**: 4번 설계대로 표·화면·관리자 승인·약관.

## 6. Kay 님 결정이 필요한 것
1. **상위노출**(구인·장터·부동산·업소·동호회 하루 가격): 광고로 보고 **돈**? 아니면 끌어올리기처럼 **포인트** 유지? (제안: 돈)
2. **공동구매 참여 결제**를 포인트로 하는 지금 구조: 돈/오프라인으로 바꿀지, 공동구매 자체를 잠시 끌지. (제안: 돈 또는 오프라인)
3. **포인트 판매 중단**에 동의? 이미 산 포인트가 있으면(결제 테스트 보류라 거의 없을 것) 교환 대상에서 뺄지.
4. **환율·수수료·한도** 제안 값(1,000P=$1, 수수료 10% 최소 $1, 최소 $10, 월 $50, 연 $599) 괜찮은지.
5. **내돈내산 리뷰**가 어느 리뷰인지 (업소 리뷰 / 공동구매 후기 / 다른 것).
6. **레시피 인기 보상**은 포인트 유지 vs Entry.
7. **광고 결제 경로**: 지금 Stripe 로 바로 vs CardPointe 전환 후 vs 그 전까지 관리자 수동 등록+인보이스.
8. 기프트카드 종류(Amazon / Visa / H Mart 등 한인 마트 카드) 선호.

결정해 주시면 5번 순서대로 1단계부터 진행하겠습니다.

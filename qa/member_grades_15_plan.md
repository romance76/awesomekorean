# 회원 등급 15단계 개편 계획 (2026-10-09)

> 상태: **설계 단계 — 승인 대기** (CLAUDE.md 규칙: 설계 승인 전 코드 수정 금지)
> 이번에 반영된 것: 링 이미지 15장만 서버에 올림 (`public/images/grades/level_01.png ~ level_15.png`, 아직 어디에서도 쓰지 않음)

## 1. 현재 상태
- 등급 10단계, `app/Support/MemberGrade.php` 가 `users.lifetime_points`(누적 획득, 줄지 않음)로 **즉석 계산**. 별도 컬럼 없음 → 기준점만 바꾸면 전 회원에 즉시 반영, 데이터 이전 불필요.
- 기준점은 `point_settings.grade_N_min` (관리자 `AdminPointSettings.vue` 에서 조정). 현재 100 / 300 / 800 / 2,000 / 5,000 / 10,000 / 25,000 / 50,000 / 100,000.
- 등급은 프로필 페이지·사용자 팝업에서만 보이고, 두 곳 모두 **프로필 사진 이미지가 없음(첫 글자 원만)**.
- 정상 활동으로 포인트는 하루 약 5~25P → 현재 기준점은 너무 높음(10단계는 사실상 10년 이상).

## 4. "어떻게 올라가나요?" (등급 안내 페이지용)
등급은 **지금까지 모은 포인트 총량**으로 정해지고, 포인트를 써도 내려가지 않음.
- 가입 10P(1회) · 프로필 완성 30P(전화·주소·도시·주·우편번호, 1회)
- 로그인 하루 2P · 일일 룰렛 하루 1회(최대 30P)
- 글/댓글/장터/구인/부동산/Q&A/레시피/공동구매 등 작성 건당 2P, 합산 하루 3건
- 내 글에 좋아요 받기 1P(누른 사람 기준 하루 5개까지 인정)
- 게임: 레벨업 3P · 신기록 10P · 아케이드 판당 최대 5P
- 안심서비스 체크인 5~50P · 장터 판매완료 10P · 채용확정 20P · 부동산 거래완료 50P · 공동구매 참여 5P/완료 50P · Q&A 채택 10P+현상금
- 안내 페이지의 숫자는 하드코딩하지 않고 서버 값(`/api/member-grades`, 관리자 설정)에서 읽어 항상 일치시킴.
- 참고: 기존 `PointRules.vue` 는 "게시글 3P·댓글 3P"라고 되어 있으나 실제는 2P → 같이 정정.

## 5. 단계별 혜택 (우선순위, 포인트 직접 지급은 제외)
1. 프로필 사진 링 (이번 개편) 2. 닉네임 옆 등급 이름/색 3. 프로필 진행 막대·"다음 단계까지 N P"
4. (후속) 광고·상위노출 할인 9단계~ 5. 프로필 꾸미기 6단계~ 6. 전용 이모티콘 8단계~ 7. 끌어올리기 무료 횟수(한도 필수)

## 6. ⚠ 링 오픈 전에 먼저 막아야 할 포인트 파밍 구멍 (코드로 확인함)
| | 위치 | 문제 |
|---|---|---|
| A | `POST /api/games/scores` (`GameScoreController::store`) | 점수를 클라이언트가 보냄, 서버 검증·횟수 제한 없음 → 점수 5 이상으로 반복 호출하면 호출마다 5P (확인함) |
| B | `POST /api/games/result` (`GameRecordController`) | 레벨업 3P·신기록 10P 한도 없음, `time_ms` 를 계속 줄이면 신기록 반복 (에이전트 조사, 직접 확인은 A·C만) |
| C | `POST /api/elder/checkin` (`ElderController::checkin`) | 쿨다운·일일 한도 없음 → 호출마다 5~50P (확인함) |
| D | Q&A 현상금 걸고 삭제 반복 | 환불이 `addPoints` 라 lifetime 이 늘어남 (에이전트 조사) |
| E | 구매·환불·환전·홀드 수입도 lifetime 에 반영됨 | 결제만 해도 등급이 오름 (정책 결정 필요) |
| F | 9/12 lifetime 백필 시 게임머니 환전 로그 포함 의혹 | `point_logs.type='game_money_in'` 양수 합계 점검 필요 |
- 다계정: 가입 10P + 프로필 30P, 좋아요 보상 쌍 한도 없음 → 인증 조건·쌍 상한 도입 권장.
- 부정 적발 시 등급을 낮출 정식 도구 없음 → 관리자 "lifetime 조정(사유 로그)" 권장. 기본 정책은 자동 강등 없음.

## 7. 구현 순서 (승인 후)
1. **파밍 구멍 차단**(A·B·C·D) + E 정책 결정, F 점검 쿼리 실행 → 별도 승인
2. 마이그레이션: `grade_2~10_min` 새 값으로 갱신 + `grade_11~15_min` 추가 (적용 전 라이브 현재 값 확인, 관리자가 바꿨다면 덮어쓸지 결정), 오름차순 검증
3. `MemberGrade.php` 15단계(이름·링 경로·설명·메모이즈 `levelFor()`), `GET /api/member-grades`
4. `UserAvatar`(GradeAvatar) 컴포넌트 신규 (이미지 없으면 이니셜, `/storage/` 경로 정규화, 40px↑에서 링)
5. 적용 1차: 프로필, 사용자 팝업, 내 아바타(NavBar), 마이페이지
6. **회원 등급 안내 페이지**(`/points/grades` 등): 15단계 표(링 이미지), 내 현재 단계·진행률, 올리는 법, FAQ, 구→신 대응표. 포인트/프로필 화면에서 링크
7. 적용 2차: 댓글·글 상세·친구·채팅 참가자 등 (`User::grade_level` accessor + select 에 `lifetime_points` 추가, 컬럼 없으면 null → 링 생략). 약 50곳 점진 적용
8. 이미지 320px WebP 사본, 단위 테스트(경계값), 공지

## 8. 결정이 필요한 것
1. 등급 이름·기준점 초안(§3) 승인/수정
2. 파밍 구멍 차단을 링 오픈 전에 먼저 할지 (강력 권장)
3. 구매/환불/환전 포인트를 등급에 반영할지 (권장: 제외)
4. 기존 9·10단계 회원이 모두 15단계가 되는 것 — "명예의 전당" 칭호를 따로 둘지
5. `lifetime_points` 숫자를 공개 JSON에 노출해도 되는지 (권장: 등급 번호만 노출)

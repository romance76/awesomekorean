# 공동구매 구조 변경 계획서 (3단계) — Kay 확인용

작성: 2026-10-11 UTC · **코드는 아직 아무것도 바꾸지 않았음.** 아래 "결정 필요" 7가지에 답해 주시면 바로 만들기 시작합니다.

## 1. Kay 가 정한 방향 (그대로 반영)
1. 공동구매(이벤트)를 **요청하는 사람(주최자)** 에게만 어코가 **오픈 수수료**를 받는다.
2. **참가자는 결제 없음** (포인트 결제 폐지).
3. 이벤트가 끝나면 **참가한 사람의 목록과 정보를 주최자에게 제공**한다.
4. 카드 결제는 **환불 불가**, 카드 최소 결제 금액은 관리자 결제 설정(지금 $5) 기준, 인보이스는 정식 양식(카드 종류·끝 4자리).

## 3. 새 구조

### 3-1. 주최자 오픈 수수료 (카드, Stripe)
```
등록(카드 확인 = 보류만) → 관리자 승인 때 청구 → 모집 시작
                       └→ 반려/취소 시 청구 없이 보류 해제
```
- 광고(배너·텍스트)와 **똑같은 흐름**(`DirectPayments`: begin → markAuthorized → capture/release) — 새 결제 종류 `groupbuy`.
- 금액: 관리자 › 가격 센터 › 광고 가격 탭에 **"공동구매 오픈 수수료"** 입력칸 추가(기본 $10, 센트 단위로 저장하되 달러로 환산 표시). 0으로 두면 수수료 면제.
- 카드 최소 결제 금액(`CardLimits`, 지금 $5) 미만이면 등록 화면에서 안내·서버에서 거절.
- 청구된 뒤에는 **환불 불가**(화면·인보이스에 명시). 청구 전(보류)에 반려·취소되면 전액 그대로 풀림.
- Stripe 보류는 약 7일 뒤 자동 해제 → 관리자 목록에 "보류 만료 임박"(등록 후 5일) 표시, 승인 시 만료됐으면 "주최자에게 다시 신청 안내" 문구.
- 인보이스: 종류 "공동구매 오픈 수수료 / Group buy open fee", 품목에 제목, 정식 양식 그대로. 매출 현황에 "공동구매 수수료" 줄 추가.
- 기존 13건: **수수료 면제(grandfathered)** 로 표시(`fee_status='waived'`).

### 3-2. 참가자 무료 + 정보 제공 동의
- `join()` 에서 포인트 차감 제거 → 참가 즉시 확정(`status='paid'`, `payment_type='none'`, `paid_amount=0` — 기존 `payment_method='none'` 분기와 같은 결과).
- 참가 시 **동의 체크 필수**(아래 문구), 동의 시각과 **그때의 연락처 스냅샷**(이름·이메일·전화)을 참가 기록에 저장(`consent_at`, `contact_snapshot`). 전화가 없으면 "마이페이지에서 전화번호를 등록해 주세요" 안내(이메일은 필수).
- 참가 취소는 이벤트가 확정되기 전까지 가능(지금 규칙 유지) — 취소하면 동의도 철회(명단에서 빠짐).
- 기존 모집 중 10건도 **새 참가는 무료**(마이그레이션으로 `payment_method='none'` 설정). 이미 포인트로 참가한 사람은 예전처럼 취소·반려 시 환불.
- 참가 보너스 포인트(`groupbuy_join_bonus`)는 그대로 유지.

### 3-3. 종료 후 명단 제공
- 주최자 전용: `GET /groupbuys/{id}/roster`(화면) · `…/roster.csv`(내려받기). 내용: **이름·이메일·전화·수량·참가 시각** — **동의한 참가자만**.
- 열리는 때: **이벤트가 종료된 뒤** — 제안: 관리자 "완료" 처리 또는 마감 기한이 지난 뒤, 또는 주최자가 "모집 종료" 를 누른 뒤.
- 명단을 열 때 주최자에게 **"이 정보는 이 공동구매 진행 목적으로만 쓰겠습니다" 확인 체크** 요구, 열람·내려받기마다 **기록**(누가·언제·몇 명 — 새 표 `groupbuy_roster_logs`), 관리자도 볼 수 있음.
- 공개 참가자 목록(이름만)은 그대로 — 이메일·전화는 어떤 공개 API 에도 안 나가게 서버에서 한 번 더 확인.
- 참가자에게는 동의한 내용과 시각을 마이페이지 "참여한 공동구매"에서 보여 줌.

### 3-3b. 동의 문구 (안)
> **참가 정보 제공 동의** — 이 공동구매가 끝나면 내 **이름, 이메일, 전화번호**가 주최자에게 전달되는 것에 동의합니다. 주최자는 이 정보를 공동구매 진행(안내·정산·배송) 목적으로만 쓸 수 있어요. 동의하지 않으면 참가할 수 없어요. 참가를 취소하면 동의도 철회돼요.
> **상품 대금** — 상품 대금과 배송은 참가자와 주최자가 직접 정산해요. 어코는 대금·배송·환불에 관여하지 않아요.

## 5. 작업 순서 (각 단계마다 `scripts/ship.sh` 로 배포·검증, 앞 단계가 안전해야 다음으로)
1. **DB 칸 추가 + 기존 데이터 표시**(면제·무료 참가 설정) — 화면 변화 없음.
2. **참가 무료 + 동의 저장** (join 변경, GroupBuyDetail 참여 UI, 마이페이지 동의 표시).
3. **오픈 수수료**: 설정값·등록 때 카드 보류·승인 때 청구·반려 때 해제·인보이스·매출·관리자 표시.
4. **종료 후 명단**: 주최자 화면·CSV·열람 기록·관리자 열람.
5. **마무리**: 약관·개인정보 처리방침 문구 개정(관리자 › 사이트 설정 › 약관 관리에서 Kay 가 최종 확인), 안내 문구 전체 점검.
각 단계 시험: 서버에서 롤백되는 트랜잭션으로(운영 DB 흔적 없음) + Stripe 테스트 카드 4242 4242 4242 4242 로 Kay 와 한 번.

## 6. 위험과 대비
- **기존 참가 기록·환불**: 건드리지 않음. 참가 기록의 `payment_type` 기준 환불 경로를 그대로 둔다(테스트: 포인트 참가 → 취소 → 포인트 복구).
- **카드 승인 실패**: 승인 시 청구가 안 되면 승인하지 않고 이유를 보여 준다(무료 게재 방지, 광고와 동일).
- **개인정보**: 이메일·전화는 명단 API(주최자·관리자만)에서만, 모든 열람 기록. CSV 는 주최자 본인만. 공개 API 점검.
- **법적**: 개인정보 제공 동의 문구·약관 개정, 상품 대금 비관여 문구는 **법률 검토를 권장**합니다(제가 법률 자문은 못 해요).
- **오남용**: 가짜 계정으로 명단을 모으는 것 방지 → 명단은 "동의한 실제 참가자만", 최소 참가 인원(`min_participants`) 이상일 때만 열기(제안), 정지·더미 계정 표시 제외.

## 7. Kay 님 결정이 필요한 것 (제 제안 포함)
1. **오픈 수수료 금액** — 제안 **$10**(가격 센터에서 언제든 변경, 0이면 면제).
2. **수수료 청구 시점** — 제안: 등록 때 카드 **보류**, **관리자 승인 때 청구**(반려면 청구 없음). 대안: 등록 즉시 청구(반려 시 환불 문제가 생겨 비추천).
3. **명단에 넣는 정보** — 제안: **이름·이메일·전화** + 수량·참가 시각(주소는 제외, 배송이 필요한 공동구매는 나중 단계). 괜찮은지?
4. **명단이 열리는 때** — 제안: 관리자 "완료" 처리 **또는** 마감 기한이 지난 뒤 **또는** 주최자가 "모집 종료"를 누른 뒤. 괜찮은지?
5. **기존 13건** — 제안: 수수료 **면제**, 새 참가는 **무료**, 이미 포인트로 참가한 31+103건은 그대로(취소·반려 시 환불). 괜찮은지?
6. **상품 대금** — 제안: 어코는 관여하지 않고 참가자↔주최자 직접 정산(안내 문구에 명시). 어코가 대금을 받아 주는 방식은 이번 범위에 **없음**. 맞는지?
7. **약관·개인정보 처리방침** — 위 동의 문구를 약관에 넣을 건데, 전문가 검토 후 최종 문구를 Kay 가 정해 주실 수 있는지(제가 초안만 쓰고 관리자 약관 화면에서 최종 수정).

**답 예시**: "1~7 제안대로 진행" 또는 "1번만 $15, 나머지 제안대로".
